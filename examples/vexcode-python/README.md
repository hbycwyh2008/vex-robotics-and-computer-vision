# VEXcode V5 Python Classroom Examples

These examples support the driver-control and autonomous-control units. They are intentionally small and readable so students can connect each line of code to a physical robot behavior.

## Important: configure devices first

VEXcode generates device objects from the **Devices** configuration. The exact Python names depend on the names chosen in the student's project. For example, a configured drivetrain may be named `drivetrain`, while individual motors might be named `left_motor` and `right_motor`.

Therefore, the snippets in this folder are **patterns**, not blind copy/paste solutions. Students must:

1. inspect the physical robot;
2. record the Brain port map;
3. configure the same devices in VEXcode;
4. use the generated device names in their program;
5. test at low speed in a safe area.

Never invent port numbers to make an example compile.

## Progression

1. `01-basic-drivetrain.py` — velocity, forward/reverse movement and turning
2. `02-functions-and-square.py` — reusable motion functions and accumulated error
3. `03-distance-stop.py` — perception → threshold decision → action
4. `04-inertial-turn.py` — feedback-based turning pattern
5. `05-autonomous-state-machine.py` — explicit autonomous states

## Teaching rule

Students should be able to answer three questions for every example:

- What information enters the program?
- What decision or transformation happens?
- What physical action results?

## Safety

For every new motion program:

- begin with conservative speed;
- keep the robot in a clear test area;
- be ready to stop the program;
- test one new behavior at a time;
- investigate unexpected motion before increasing speed.

## Version note

VEXcode APIs can change. Before teaching from a snippet, compare it with the current VEXcode V5 Python API and the device configuration generated by the classroom version of VEXcode.
