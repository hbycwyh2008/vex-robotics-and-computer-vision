# Lesson 07 — Driver Control Engineering Challenge

## Course position
Weeks 11–12 · Driver Control and Robot Motion Programming

## Learning objectives
Students will be able to:
- apply drivetrain programming and controller mapping in a constrained challenge;
- collect performance data across repeated trials;
- distinguish driver skill problems from control-code or mechanical problems;
- make one evidence-based improvement at a time;
- document iteration as an engineering process.

## Challenge
Complete a teacher-defined driving course containing at minimum:
- a narrow passage;
- a turn requiring precision;
- a target stopping zone;
- a reverse segment or return route.

Optional game objects may be added, but the challenge should remain focused on drivetrain control rather than complex mechanisms.

## Baseline trial
Teams run the course without last-minute code changes.

Record:
- completion time;
- number of boundary/contact errors;
- missed target zones;
- qualitative control problems.

## Diagnose
Classify each major problem:
- **Driver** — timing, anticipation, joystick technique.
- **Software** — mapping, deadband, sensitivity, direction.
- **Mechanical** — friction, looseness, alignment, wheel/shaft issue.
- **Procedure** — inconsistent start position or testing method.

## Iteration rule
Teams may change only one major variable before the next measured trial.

Examples:
- lower maximum speed;
- adjust deadband;
- change control mapping;
- repair drivetrain alignment;
- change driver technique.

Run at least three measured trials after the baseline.

## Data table
Students create a table containing:
- trial number;
- change made;
- time;
- errors;
- observation;
- keep/revert decision.

## Engineering discussion
Fastest is not automatically best. A competition robot needs a balance among:
- speed;
- controllability;
- reliability;
- repeatability.

Connect this to optimization: improving one metric can make another worse.

## Evidence to submit
- challenge data table;
- final controller configuration / code;
- photo or sketch of the course;
- one paragraph explaining the most useful iteration;
- one paragraph identifying a change that did not help and why.

## Mastery checkpoint — Unit 02
Students should now be able to:
- configure VEX devices;
- command drivetrain motion;
- use Python variables/functions in robot-control context;
- use Controller input;
- debug across mechanical/software layers;
- improve a system using measured evidence.

## AI use
AI may help analyze the team's own trial table or propose hypotheses. It may not fabricate measurements. Students must clearly distinguish observed data from AI suggestions.

## Next unit
The robot begins sensing the environment directly. Students will move from human-operated input toward autonomous behavior using sensors and feedback.
