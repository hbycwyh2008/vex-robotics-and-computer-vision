# Hardware Failure and Instructional Continuity Plan

Robotics hardware will fail; instruction should continue.

## First response
Power down if needed → record symptom → classify mechanical/electrical/configuration/software/power/sensor → isolate smallest reproducible subsystem → document while investigating.

## Productive fallback
Port/wiring verification; code review/refactor; pseudocode/state diagram; test planning; notebook reconstruction; mechanism analysis; OpenCV on saved media; assessment corrections; peer review; inventory/maintenance.

## Spares
Where possible maintain spare Smart Cables, known-good battery, known-good diagnostic motor, common fasteners/collars/spacers/shafts, and a teacher/reference subsystem.

Do not hand students a silently repaired robot; involve them in diagnosis.

Escalate immediately for battery damage/swelling, unusual heat/smell, exposed conductor, repeated Brain power failure, or hazardous tools/metal.

Record significant failure date, symptom, cause, replacement/repair, prevention and pacing impact.
