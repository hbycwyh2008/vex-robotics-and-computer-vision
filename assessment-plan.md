# Assessment Plan

This course uses portfolio-based, project-centered assessment with frequent low-stakes checks. The goal is to assess **engineering thinking** — building, debugging, iterating, documenting — not just final results.

## Assessment Types

### 1. Formative Checks (ongoing)
Quick, low-stakes checks during lessons: exit tickets, predictions, debugging logs, and mini-demos. Used to adjust teaching, not for major grades. See [assessments/formative-checks.md](assessments/formative-checks.md).

### 2. Unit Quizzes
Short concept checks at the end of each unit (vocabulary, core ideas, reading a diagram or code snippet). See [assessments/unit-quizzes.md](assessments/unit-quizzes.md).

### 3. Project Assessments
The core of the grade. Each project is graded with a matching rubric:

| Project | Rubric |
|---|---|
| Engineering notebook (ongoing) | [engineering-notebook-rubric.md](rubrics/engineering-notebook-rubric.md) |
| Robot builds | [robot-build-rubric.md](rubrics/robot-build-rubric.md) |
| Robot programming | [robot-programming-rubric.md](rubrics/robot-programming-rubric.md) |
| Computer vision projects | [computer-vision-project-rubric.md](rubrics/computer-vision-project-rubric.md) |
| Final project | [final-project-rubric.md](rubrics/final-project-rubric.md) |
| Presentations | [presentation-rubric.md](rubrics/presentation-rubric.md) |

See [assessments/project-assessments.md](assessments/project-assessments.md).

### 4. Final Assessment
The integrated robotics + vision project, its portfolio documentation, and a presentation. See [assessments/final-assessment.md](assessments/final-assessment.md).

## What Every Rubric Assesses

All rubrics use a 4-level scale and assess a consistent set of dimensions:

- Technical correctness
- Debugging process
- Documentation quality
- Iteration
- Team collaboration
- Final demonstration
- Reflection

## 4-Level Scale

| Level | Label | Meaning |
|---|---|---|
| 4 | Exceeds Expectations | Independent, polished, goes beyond requirements |
| 3 | Meets Expectations | Meets all requirements competently |
| 2 | Approaching Expectations | Partially meets requirements; needs support |
| 1 | Beginning | Early progress; major gaps |

## Suggested Grade Weighting

| Category | Weight |
|---|---|
| Engineering notebook & portfolio | 20% |
| Formative checks & quizzes | 15% |
| Projects | 40% |
| Final integrated project | 20% |
| Presentation & reflection | 5% |

> Adjust to your school policy. Emphasize process (debugging, iteration, documentation) so students are rewarded for engineering habits, not luck.

## Academic Integrity and AI Use

Students may use AI tools (including coding assistants) but must **disclose** how they used them and be able to **explain and test** any code they submit. Undisclosed or unexplained AI-generated work does not meet expectations. See [student-handouts/github-markdown-portfolio-guide.md](student-handouts/github-markdown-portfolio-guide.md).
