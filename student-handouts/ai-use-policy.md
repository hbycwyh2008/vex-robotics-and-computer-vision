# AI Use Policy — VEX Robotics and AI Vision

AI tools may support learning, coding and debugging, but they do not replace engineering evidence or student understanding.

## Allowed Uses
Students may use AI to:
- explain VEX/Python/OpenCV concepts;
- interpret error messages;
- suggest debugging hypotheses;
- propose test cases;
- review code organization;
- help summarize student-collected data;
- improve clarity of documentation after the student provides the technical content.

## Not Acceptable as Evidence
AI output does **not** prove that:
- the robot is wired correctly;
- a mechanism is reliable;
- a sensor threshold is appropriate;
- a vision system is accurate;
- autonomous code works;
- a design is safe or competition-legal.

Those claims require direct observation, official documentation and/or physical testing.

## Student Responsibilities
When AI contributes meaningfully, students must be able to:
1. disclose what AI helped with;
2. explain the final code/design in their own words;
3. identify which suggestions were accepted or rejected;
4. test all technical suggestions on the actual system;
5. verify factual claims against official documentation when needed;
6. show debugging or revision evidence rather than submitting raw AI output.

## Code Rule
If a student cannot explain what a generated line/function/state does, that code is not ready to submit.

## Data Rule
Never ask AI to invent experimental values, trial results, detection accuracy, success rates or engineering measurements.

## Documentation Rule
Use this disclosure format:

> **AI tool:**
>
> **Used for:**
>
> **Suggestion received:**
>
> **How I verified it:**
>
> **What I changed / learned:**

## Assessment Principle
AI assistance by itself does not lower a grade when it is allowed, disclosed, understood and verified. Undisclosed or unexplained AI-generated work does not demonstrate mastery.
