## Shared Course Culture

The shared CS learning flow is:

> **Learn → Practice → Rebuild → Share**

VEX Robotics then applies that learning culture through its engineering cycle:

> **Predict → Build / Program → Test → Debug → Redesign → Retest → Document → Explain / Transfer**

## How to Use Each Poster

### Our Classroom Flow

Display throughout the year. Refer to it when students ask whether completing a guided build or getting code to run once means the learning is finished.

In VEX, **rebuild** may mean:

- rebuilding or reconfiguring a mechanism;
- recreating device configuration;
- rewriting control logic;
- repeating a valid test procedure;
- recreating a sensor or vision pattern with less support.

### Mastery Level

Use during demonstrations, rebuild checks, project conferences, and individual reflections.

A working robot is not automatically high mastery. Students progress from following instructions toward independent rebuilding, debugging, redesign, and transfer.

Mastery Levels 0–5 are **not** the same as the existing 4-level project rubric scale.

### AI Use Policy

Use whenever AI-assisted coding or technical explanation is allowed.

In robotics, AI-generated suggestions must be checked against:

- real hardware behavior;
- actual measurements;
- repeated tests;
- documentation;
- student technical understanding.

AI must never invent test data, measurements, observations, or robot performance.

### CS Competition Pathways

Use as an optional enrichment reference. The VEX course directly connects to the **Robotics & Engineering** pathway, while students may also extend into programming, cybersecurity, AI, or data science.

Competition participation is not required for core course credit unless separately assigned.
