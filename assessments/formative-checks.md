# Formative Checks

Use these as low-stakes checks during or at the end of lessons. They are diagnostic, not major project grades.

## Hardware / Build Checks
- Identify a shaft, spacer and shaft collar and explain the difference.
- Given a drivetrain photo, identify one likely alignment problem.
- Explain why a loose shaft collar can create inconsistent motion.
- Name the first three things you would inspect if a wheel does not turn.

## VEXcode / Programming Checks
- Match a physical motor port to the VEXcode configuration.
- Explain the difference between a variable and a function in robot control.
- Predict what happens if one drivetrain motor is reversed incorrectly.
- Explain why changing several variables at once makes debugging weaker.

## Driver Control Checks
- Compare tank drive and arcade drive.
- Explain what a joystick deadband does.
- Describe one trade-off between top speed and controllability.

## Sensors / Autonomous Checks
- Distinguish a sensor reading from a decision rule.
- Given repeated sensor values, choose a threshold and justify it.
- Explain open-loop vs feedback-based turning.
- Draw a three-state autonomous routine with transition conditions.

## Engineering Design Checks
- Identify driver and driven gears.
- Predict whether a gear ratio favors speed or torque.
- Write a testable hypothesis for a mechanism change.
- Explain why a failed but well-tested design change can still be valuable evidence.

## Computer Vision Checks
- Explain what a digital image is in terms of pixels and channels.
- Explain why OpenCV often uses BGR while displays are commonly discussed as RGB.
- Describe what an HSV mask does.
- Explain the difference between a false positive and false negative.
- Explain how a contour becomes a bounding box and target center.

## AI Robotics Integration Checks
- Complete the architecture: Perception → ___ → Action.
- Explain why target loss needs a fallback behavior.
- Give one reason a vision-guided robot might oscillate around the center.
- Name one environmental condition that could make a color detector fail.

## Quick Exit Ticket Template
1. What worked today?
2. What evidence shows it worked?
3. What failed or remained inconsistent?
4. What is your next hypothesis/test?
5. Did AI contribute to today's work? If yes, what did you verify?

## Teacher Use
Use responses to decide whether the next class should begin with:
- reteaching;
- a live debugging demo;
- additional measurement practice;
- a short code-reading task;
- extra build time;
- extension work for advanced teams.
