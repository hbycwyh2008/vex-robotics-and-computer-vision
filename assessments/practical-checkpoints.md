# Practical Checkpoints — Teacher Use

These checkpoints verify individual mastery. Team project success alone is not sufficient.

## Scoring Scale Per Skill
- **0 — Not demonstrated:** cannot perform/explain even with substantial prompting.
- **1 — Guided:** succeeds only with step-by-step help or copies a visible pattern.
- **2 — Independent:** performs/explains correctly with normal reference materials.
- **3 — Transfer/debug:** adapts the skill, diagnoses a fault or applies it to a new case.

A project rubric measures project quality; this scale measures student independence.

---

## C1 — Course / Lab Ready (End Week 2)
Student can:
- identify major subsystem categories;
- apply power-down/battery/moving-parts safety;
- use basic VEX tools without forcing fasteners;
- distinguish shaft, spacer and shaft collar;
- create a usable engineering notebook entry;
- make a basic GitHub evidence commit.

**Pass target:** no safety-critical item at 0; most items at 2+.

---

## C2 — TrainingBot / Hardware Foundations (End Week 6)
Stations:
1. identify 6–8 components by function;
2. correct one planted shaft/fastener/support problem;
3. trace Smart Motor → cable → Brain port;
4. inspect a drivetrain and name one alignment/friction risk;
5. explain first-power safety and stop procedure;
6. rebuild one small assembly from a checklist.

**Teacher prompt:** “Show me how you know, not just what you think.”

---

## C3 — Programming / Driver Control (End Week 12)
Student can:
- verify physical/software port configuration;
- explain tank and arcade input mapping;
- explain/use deadband;
- read a short VEX/Python movement program;
- create/use a function for a robot behavior;
- identify appropriate use of variables and loops;
- diagnose a curved-drive or wrong-direction symptom using mechanical + software hypotheses;
- run a controlled motion test.

**Transfer item:** change one route requirement and modify the program structure without receiving the final code.

---

## C4 — Sensors / Autonomous Control (End Week 18)
Student can:
- read raw sensor data;
- justify a threshold from collected data;
- explain false positive / false negative in the task context;
- implement/trace a conditional;
- explain open-loop vs feedback with the robot example;
- trace a state transition;
- explain calibration/start-state importance;
- diagnose one autonomous failure from evidence.

**Transfer item:** given a new threshold or state condition, predict the behavior before testing.

---

## C5 — Engineering Design / Mechanisms (End Week 24)
Student can:
- identify driver/driven gear;
- explain speed/torque trade-off;
- identify a shaft-support/alignment problem;
- state measurable requirement/constraint;
- design a fair comparison with controlled variables;
- interpret baseline vs retest evidence;
- defend one mechanism trade-off.

**Transfer item:** new object/load/constraint → propose a design change and expected effect.

---

## C6 — Classical Computer Vision (End Week 30)
Student can explain or demonstrate:
- image shape, coordinates and color channels;
- OpenCV BGR vs RGB;
- HSV and threshold mask;
- false positive / false negative in detection;
- contour, bounding box and centroid;
- target-selection rule;
- left/center/right tolerance band;
- one real failure traced to a pipeline stage;
- how classical CV differs from CNN/learned vision.

**Transfer item:** given a new lighting/background failure, propose the first diagnostic check—not a random threshold change.

---

## C7 — AI Vision / Robot Integration (End Week 33)
Student can:
- draw perception → decision → action architecture;
- explain why layers are separated;
- test decision logic with mocked perception;
- explain target-center error and tolerance;
- explain oscillation/overshoot qualitatively;
- describe MobileNet/transfer learning at application level;
- explain IoU and why NMS is needed;
- identify embedded deployment constraints;
- demonstrate safe target-loss fallback;
- classify a failure by subsystem/layer.

**Transfer item:** choose classical vs learned vision for a new scenario and justify from data/compute/environment constraints.

---

## C8 — Final Engineering Defense (Week 36)
Every student must independently answer questions from at least four areas:

1. **Architecture:** trace data/action through the final system.
2. **Own contribution:** identify exact code/build/test work personally completed.
3. **Engineering decision:** justify one design choice and rejected alternative.
4. **Failure/debugging:** give symptom → hypothesis → test → evidence → decision.
5. **Validation:** explain why the data supports one claim.
6. **Limitation:** distinguish limitation from bug.
7. **AI use:** identify assistance and verification.
8. **Transfer:** predict how system changes under a new requirement.

A polished team demo with weak individual understanding does not meet the course mastery goal.
